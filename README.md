# Logstream Alerting Service

This repository contains the Alerting Microservice for the Logstream application. It is built as a fully decoupled, event-driven architecture using AWS Serverless technologies (Lambda, EventBridge, SNS, API Gateway).

## Architecture Overview

This microservice is responsible for handling user subscriptions and disseminating critical alerts generated by the Machine Learning Processing pipeline. It operates entirely outside of the private VPC, demonstrating a true decoupled microservice design.

The service consists of two primary AWS Lambda functions managed via AWS SAM (Serverless Application Model):

### 1. Publisher Lambda (Event-Driven)
The Publisher Lambda is triggered automatically by an AWS EventBridge Rule.
- **Trigger:** Listens to the custom EventBus (`Logstream-alert-bus`) for events matching the `com.logstream.processing` source and `VolumeAnomalyDetected` detail-type.
- **Functionality:** When an anomaly is detected by the ML pipeline, the event payload containing the cluster ID and sample logs is sent to EventBridge. The Publisher Lambda extracts this context, formats a comprehensive incident report, and publishes it to an Amazon SNS Topic.
- **Decoupling:** By relying on EventBridge rather than querying the RDS database directly, this service remains fully decoupled from the stateful storage layer.

### 2. Subscriber Lambda (API-Driven)
The Subscriber Lambda handles HTTP requests from the frontend to manage SNS subscriptions.
- **Trigger:** Invoked via AWS API Gateway using HTTP POST requests (`/subscribe` and `/unsubscribe`).
- **Functionality:** Accepts an email address from the client, retrieves the internal SNS Topic ARN securely from environment variables, and utilizes the AWS SDK to subscribe or unsubscribe the user from the alert topic.
- **Integration:** To adhere to best practices and avoid CloudFormation stack deletion conflicts, the API routes are attached to an existing, external API Gateway using raw CloudFormation `AWS::ApiGatewayV2::Route` and `AWS::ApiGatewayV2::Integration` resources.

## Deployment Instructions

This project uses AWS SAM for deployment. Ensure you have the AWS CLI and SAM CLI installed and configured.

1. Build the application:
   ```bash
   sam build
   ```

2. Deploy to AWS:
   ```bash
   sam deploy --guided
   ```
   During the guided deployment, provide a unique stack name (e.g., `logstream-alerting-stack`) to ensure it deploys as an independent microservice stack rather than overwriting existing infrastructure.

## Environment Variables
The SAM template (`template.yaml`) defines the following global environment variable for the Lambdas:
- `SNS_TOPIC_ARN`: The ARN of the SNS topic where alerts are published and users are subscribed.

## Security Considerations
- The API Gateway integration ensures that AWS ARNs are never exposed to the client frontend. The frontend only passes the target email address.
- Standard IAM policies are strictly scoped within the SAM template to grant the Lambdas only the exact `sns:Publish`, `sns:Subscribe`, and `sns:Unsubscribe` permissions required.
